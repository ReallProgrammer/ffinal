# Collection Room verification

Verified in the cloud workspace on October 9–10, 2026 using Node 24, system Chromium, actual PostgreSQL and a local S3-compatible storage service. No fixtures were uploaded to production.

- **Backend:** 20 passed, zero failed or skipped, including owner authorization, anonymous/forged-session rejection, all 13 object schemas, draft/private-asset isolation, publishing, edits, ordering, crop originals, invalid uploads, GLB/glTF validation and a disposable-schema legacy migration/reconnection check. The backend test runner serializes suites because ordering tests touch a shared test database.
- **Browser regression:** the full 80-case desktop/mobile run produced 73 passes, six expected skips for pointer-only mobile interactions, and one window-drag timing failure. The test sampled the existing opening animation before it finished; it now waits for finite animations. Its targeted rerun passed without changing the window implementation.
- **Final affected browser checks:** five passed, one expected mobile drag skip. These cover the corrected drag check and both desktop/mobile collection journeys after final changes: all 13 formats, texture-failure recovery, selected-object isolation/return, real PDF spreads, page turns, keyboard controls, zoom, owner crop/preview/publish, and the WebGL-unavailable details fallback. Mobile additionally used the embedded 2048 px textured GLTF fixture to exercise model texture resizing. Existing PDF/EPUB, refresh, edit and sign-out journeys passed on desktop and mobile in the full run.
- **Production build:** TypeScript and Vite passed with the actual `/ffinal/` asset base and the configured Render API URL. PDF.js fonts/maps/worker support are bundled. The lazy Three.js dependency produces a size advisory; it is not part of the initial desktop bundle.
- **Container:** the production Docker image built and started as user `node`. A real API-created certificate, artwork bytes and authenticated owner session survived a container restart. Probe records/assets were removed after verification.
- **Secrets:** changed files were checked against local private configuration; no owner password, password hash, database URL or storage secret was found in release sources. Environment and test credential files remain ignored/outside the checkout.

## Limits and production follow-up

Production Render access has been restored. The existing health endpoint returned status ok, and the pre-upgrade public API reported one item and one shelf. The compatible backend deployed from main commit b30cd77. Its live API returns all 13 formats and status ok. A before/after check confirmed the existing published item and shelf IDs, metadata, artwork references and ordering were preserved, with the book type added by migration. The API allows the GitHub Pages origin through CORS. No owner authentication or production mutation was performed during these read-only checks. Existing Render/Supabase credentials are reused. Follow [the backend-first rollout](collection-deployment.md).

GLB/glTF support is deliberately restricted to validated static models with embedded resources. EPUB uses sanitized reflowable text rather than the PDF page-turn renderer. Test artwork and documents verify functionality; final personal certificates, covers and model assets must be supplied by the owner. The missing reference screenshot could not be compared visually.
